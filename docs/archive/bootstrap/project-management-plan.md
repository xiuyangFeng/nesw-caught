# 项目执行计划

## 1. 项目边界

第一阶段只做单用户、本地运行、SQLite 存储的产品闭环。目标是形成可长期日常使用的消息工作台，而不是一次性演示页面。

## 2. 阶段划分

### 阶段一：基础设施

- 初始化前后端项目
- 建立配置、日志、数据库和本地运行脚本
- 明确数据源配置格式
- 落定 UTC 存储与按市场展示的时区规范
- 为新闻和正文建立 SQLite FTS5 索引

### 阶段二：数据采集闭环

- RSS 采集
- 分级抓取频率
- 新闻去重
- 正文抓取
- 股票提及识别
- 行情拉取
- 数据入库
- 统一 HTTP 请求客户端和源健康记录

### 阶段三：用户可用闭环

- REST API
- 单向推送增量更新
- Dashboard、News Feed、Watchlist 页面
- 情绪标签和异动展示

### 阶段四：降噪和增强

- 主题聚合
- 重要性排序
- 异常降级
- 数据质量记录
- 健康检查、备份和清理策略

### 阶段五：扩展准备

- AI 能力接口
- 通知事件模型
- 演进文档和迁移预案
- 本地 LLM 和 RSSHub 接入预案

## 3. 优先级管理

### P0

- 新闻能进来
- 数据能存住
- 页面能看
- 异常不崩
- 时间和搜索能力从一开始就不返工

### P1

- 正文可抓
- 股票可关联
- 主题可聚
- 情绪可看
- 自选股可跟

### P2

- AI 可接
- 通知可发
- 指标可观察

## 4. 里程碑验收

### M1 完成标准

- 仓库结构清晰
- 本地一键启动可用
- 数据库 schema 可初始化
- 时区规范确定
- FTS5 虚拟表完成

### M2 完成标准

- 至少一批 RSS 源稳定采集
- 去重生效
- 行情数据可定时刷新
- 新闻和股票关联可落库
- 源健康状态可记录

### M3 完成标准

- 页面可展示新闻、自选股和情绪
- 单向推送通道能推送新增消息
- 基本搜索和筛选可用

### M4 完成标准

- 支持正文抓取失败回退
- 支持外部源失败重试
- 测试和运行手册齐备
- 备份和清理任务可运行

### M5 完成标准

- AI 接口层和通知事件层已预留
- 未来扩展不会推翻现有模型

## 5. 风险和处理

### 数据源风险

对关键 RSS 源维护备选方案，抓取失败要可追踪。

### 技术复杂度风险

先用简单可解释方案跑通，不在第一阶段引入复杂算法。

### 范围失控风险

任何新需求先判断是否提升“长期自用价值”，否则延后。

### 可维护性风险

所有采集逻辑必须模块化，避免散落在路由或页面代码中。

### 外部依赖风险

RSSHub、本地 LLM 和第三方行情源都属于增强能力，必须可关闭且不影响主链路。
