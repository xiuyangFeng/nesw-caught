# news-caught 项目优化建议与迭代设计方案

根据对项目的全面梳理，为了提升系统的用户体验、系统稳定性、性能及可审计性，我们从前端交互、后端性能、大模型接入和数据存储等多个维度提出以下 10 项优化方向。

---

## 1. 10 个项目优化方向汇总

| 维度 | 优化点 | 当前现状 | 优化目标与价值 |
| :--- | :--- | :--- | :--- |
| **UX/前端** | **1. AI 对话多会话管理与本地持久化 (localStorage)** | 对话为单次临时会话，刷新或切页即丢失。 | 支持左侧历史会话列表，保存最近多条对话，且可在浏览器中持久保存。 |
| **UX/前端** | **2. AI 对话 Markdown 渲染与金融对比表格支持** | 直接采用纯文本 `whitespace-pre` 渲染，无法格式化列表、代码和表格。 | 实现轻量 Markdown 转换逻辑，美化代码块，并渲染 LLM 输出的股票对比表格与 LaTeX 指标。 |
| **UX/前端** | **3. 大模型流式输出中止控制 (Abort Control)** | 发送提问后无法中途停止生成，易浪费 Token 且体验较差。 | 在前端提供“停止生成”按钮，利用 `AbortController` 优雅掐断连接，后端检测连接关闭并中止上游请求。 |
| **UX/前端** | **4. 全局高品质 Toast 消息提示组件** | 模型切换、请求失败等反馈缺失或使用原生 alert。 | 建立全局 Toast 通信系统，给用户提供毛玻璃发光的高频状态反馈（成功、失败、警告、常规）。 |
| **后端/LLM** | **5. 大模型连接异常自动容灾备份切换 (Failover)** | 只指定单一活动默认配置。若 API 超时/欠费则请求直接失败。 | 允许配置“主模型配置”与“备用模型配置”。主配置故障（429/500/503等）时，自动降级请求备用模型。 |
| **后端/LLM** | **6. 大模型调用 Token 审计与额度消耗统计** | 后端在后台高频分析新闻但无统计，容易产生未知的巨额账单。 | 记录每次请求的 Input/Output Token 及 model 名称，写入 SQLite 表，并在配置页展示消耗看板。 |
| **UX/前端** | **7. 自选股添加支持模糊搜索与自动补全** | 需要输入精确的代码才能添加自选股，不够智能。 | 引入 debounce 自动补全接口，拉取匹配的股票列表供用户点击。 |
| **后端/性能** | **8. 缓存低频数据 REST 接口 (In-Memory Cache)** | 像来源健康度、LLM 配置等静态或极低频更新接口频繁查库。 | 引入简单的内存缓存修饰器，减少 SQLite 并发读的磁盘 IO，提高响应速度。 |
| **存储/后端** | **9. 数据库历史数据清理策略自定义配置** | 清理周期硬编码在后端（7天），且用户无法手动清理。 | 提供可视化配置，允许设定新闻/推文的留存时长，并提供“一键手动清理并整理碎片”按钮。 |
| **UX/前端** | **10. K线图多周期切换与关联新闻快讯面板** | K线仅支持日线，且图表的新闻标记与主列表割裂。 | 支持周线/月线/小时线切换，并在 K 线下方提供当日关键新闻汇总抽屉。 |

## 2. 迭代优化选择与详细设计

在上述 10 个优化点中，我们选择对**用户体验 (UX) 和大模型交互**提升最直观的四项进行本期迭代落地：
1. **[UX/前端] AI 对话多会话管理与本地持久化 (localStorage)**
2. **[UX/前端] AI 对话 Markdown 渲染与金融对比表格支持**
3. **[UX/前端] 大模型流式输出中止控制 (Abort Control)**
4. **[UX/前端] 全局高品质 Toast 消息提示组件**

### 2.1 模块 1：AI 对话多会话管理 (Multi-Session Storage)

在 `ChatView.vue` 内部，我们将引入侧边栏会话列表：
*   **数据模型 (Session)**:
    ```typescript
    interface ChatSession {
      id: string; // UUID 或时间戳
      title: string; // 会话标题，默认是“新对话”或第一句提问的前15字
      messages: Message[];
      newsId?: number | null; // 关联的新闻上下文 ID
      selectedConfigId: number | null; // 所选 LLM 配置 ID
      createdAt: number;
    }
    ```
*   **本地存储流程**:
    *   在 `localStorage` 中维护 `news_caught_chat_sessions` 数组和当前选中的 `active_session_id`。
    *   初始化时：如果 `localStorage` 没有会话，则自动创建一个欢迎会话；如果有，则加载。
    *   交互操作：
        *   **新建会话**：清空当前聊天，保留欢迎句。
        *   **切换会话**：载入指定会话的消息历史与关联模型、新闻上下文。
        *   **删除会话**：若删除的是当前活动会话，则自动切换至前一个，或生成全新空白会话。
        *   **重命名会话**：用户可双击会话标题进行原位重命名，或者在输入第一条提问时自动根据提问内容前 10-15 字更新标题。

### 2.2 模块 2：AI 对话 Markdown 渲染与金融表格解析

由于我们不增加重型依赖，我们在前端创建一个高性能且体积小的轻量级 Markdown-to-HTML 转换函数：
*   **解析能力**：
    *   **加粗/斜体**：`**text**` -> `<strong>text</strong>`，`*text*` -> `<em>text</em>`
    *   **代码块**：包含语言标识的 ``` 处理。生成带有黑色背景和横向滚动的 `<pre>` 容器，并在右上角配备 **“一键复制”** 按钮。
    *   **单行代码**：`` `code` `` -> `<code class="px-1.5 py-0.5 bg-white/10 rounded font-mono text-xs text-yellow-300">code</code>`
    *   **无序列表**：支持 `-` / `*` 起头的行包装进 `<ul>` / `<li>`。
    *   **金融数据表格**：识别 Markdown table（由 `|` 分隔且有第二行分割线 `|---|---|`），转换成标准 `<table>`。定义 CSS 以实现带有高斯模糊及流光边框的金融终端科技风表格。
*   **防 XSS 安全**：在输出到 HTML 之前转义原始文本的 `<` 和 `>`，确保安全性。

### 2.3 模块 3：大模型流式输出中止控制 (Abort Control)

*   **前端逻辑**：
    *   在发送请求前，创建一个 `AbortController` 实例：`currentAbortController = new AbortController()`。
    *   将 `currentAbortController.signal` 传给底层的 `fetch('/api/llm/chat')` 方法。
    *   在发送时，输入框右侧显示“停止生成”红色按钮。
    *   点击“停止生成”后，执行 `currentAbortController.abort()`，前端终止读取流，结束加载状态，并将本次生成的 `assistant` 消息标为 `[已中止]`。
*   **后端逻辑**：
    *   在 `backend/app/api/routes/llm.py` 的 `/api/llm/chat` 接口中，返回 `StreamingResponse`。
    *   使用 `async def event_generator()`。在此生成器中，通过监测 `await request.is_disconnected()`（FastAPI `Request` 对象传入）或常规生成异常，可以捕获客户端断开事件。
    *   若捕获到断开，直接退出循环，中断对上游大模型提供商的 `chat_stream` 请求，实现网络与算力资源的双向省流。

### 2.4 模块 4：全局高品质 Toast 消息提示组件 (Toaster)

*   **Toast 状态结构 (Pinia store)**:
    ```typescript
    interface ToastMessage {
      id: string;
      type: 'success' | 'error' | 'warning' | 'info';
      message: string;
      duration?: number; // 默认 3000ms 自动消失
    }
    ```
*   **视觉规范**：
    *   右上角浮动容器，多条 Toast 垂直叠加。
    *   毛玻璃特效（`backdrop-filter: blur(12px)`），背景为透明的深灰/黑底加上发光侧边框：
        *   `success`：左侧发光翠绿色（`#10B981`），呼吸灯心跳。
        *   `error`：左侧发光红色（`#EF4444`），带警告图标。
        *   `warning`：左侧发光橘黄色（`#F59E0B`）。
        *   `info`：左侧发光科技蓝（`#3B82F6`）。
    *   支持悬停暂停消失，点击立即关闭。

## 3. 验证方案

### 3.1 自动化测试
*   针对 Markdown 解析器，在 `frontend/src/utils/markdown.test.ts` 中编写单体测试，覆盖加粗、代码块、列表、表格和防 XSS 等场景。
*   针对后端连接断开中止，在 `backend/tests/test_llm_chat.py` 中编写异步连接中断验证用例，确保请求中断时后台停止迭代大模型流。

### 3.2 手动验证
*   **多会话**：新建 3 个会话并分别提问，切换不同会话确认历史消息、所选模型及关联的新闻上下文完好；刷新页面验证会话全部重现。
*   **Markdown 表格与复制**：诱导 AI 生成对比表格与代码块，观察表格样式是否具有高级科技感、表格是否对齐，测试代码块的“复制”按钮是否成功写入系统剪贴板。
*   **中断生成**：在 AI 大段流式吐字时，点击“停止生成”按钮，观察打字机是否立即静止，且再次提问不会产生干扰。
