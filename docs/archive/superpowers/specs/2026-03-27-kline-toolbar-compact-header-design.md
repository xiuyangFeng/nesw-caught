# K 线常驻周期条与紧凑头部设计

**背景**

上一轮已将 K 线详情页文案中文化，并把周期语义整理为 `日K / 周K / 月K / 年K`。但当前周期切换仍藏在右上角齿轮弹层中，切换路径偏深；同时顶部行情摘要卡片高度和宽度都偏大，在笔记本视口下会挤占过多 K 线可视区域。

**目标**

将周期切换入口调整为 K 线图上方常驻显示，支持快速切换；同时将顶部行情摘要压缩为更紧凑的条形卡片，减少横向和纵向占位，把更多空间让给主图。

## 范围

- 在 K 线图主区域顶部新增常驻周期快捷条，直接展示 `日K / 周K / 月K / 年K`。
- 顶部行情摘要区整体压缩：
  - 缩小内边距
  - 降低价格与标题字号
  - 收窄最大宽度和布局列宽
  - 精简说明文案长度
- 若齿轮弹层不再承载独立价值，则移除该入口和弹层，避免重复交互。

## 不在范围

- 不调整后端 API 和周期映射。
- 不改动 K 线主图、副图、右侧指标面板的数据逻辑。

## 方案对比

### 方案 A：常驻周期条放在 K 线摘要胶囊之上，头部卡片压成紧凑行情条

- 优点：用户切换最直接，视觉上最接近券商软件；K 线相关控件集中在图表内部，不再分散到顶部卡片和弹层。
- 缺点：需要重排图表顶部结构和测试。

### 方案 B：常驻周期条放在顶部行情卡片右侧，保留齿轮作为补充入口

- 优点：改动更小。
- 缺点：顶部卡片会继续变宽，无法解决用户指出的“太宽、太高”问题。

### 方案 C：保持现有布局，仅把弹层默认展开

- 优点：实现最小。
- 缺点：仍然占高度，且交互层级感混乱，不符合“常驻快速调整”的要求。

**推荐：方案 A。**

## 具体设计

### 顶部行情卡片

- 改成更扁的两段式布局：左侧为名称/代码/现价，右侧为紧凑指标矩阵。
- 标题和价格字号下调一档，减少多余留白。
- 宽度不再追求铺满视觉焦点，保持为摘要条而不是主视觉块。
- 去掉齿轮按钮和设置弹层，避免重复周期入口。

### 图表顶部工具条

- 放在 `KlineChart.vue` 顶部摘要胶囊之前。
- 左侧是 `日K / 周K / 月K / 年K` 常驻按钮。
- 右侧保留代码/周期/范围/K线数等摘要胶囊，作为只读信息。
- 当前激活周期高亮，切换时直接触发现有 `switchPeriod`。

## 数据流与组件边界

- `StockDetailPanel.vue` 负责压缩头部布局，并把 `currentPeriod` 和 `switchPeriod` 继续传给 `KlineChart.vue`。
- `KlineChart.vue` 新增周期工具条展示与点击事件。
- `watchlistStore.ts` 无需改动数据逻辑。

## 测试策略

- 更新 `StockDetailPanel` 测试，验证齿轮入口被移除或不再作为主入口，以及顶部卡片仍正常显示核心行情信息。
- 更新 `KlineChart` 测试，验证常驻周期按钮存在、当前周期高亮、点击后触发 `switchPeriod` 事件。
