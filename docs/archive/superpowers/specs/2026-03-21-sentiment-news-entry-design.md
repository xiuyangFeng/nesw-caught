# Dashboard 情绪新闻入口设计

## 背景

当前 Dashboard 里的 `偏利好` / `偏利空` 指标卡只承担计数展示，不能继续钻取。用户希望把这两个指标改成真正的入口，点击后看到一页规整好的新闻列表，再从列表进入单条新闻详情。

仓库现状已经具备两块基础能力：

- `DashboardView.vue` 已经计算出正负向新闻数量。
- `newsStore.loadNews({ sentiment_label })` 和现有 `NewsDetailView.vue` 已经能支撑按情绪加载新闻并查看详情。

## 目标

- 让 Dashboard 上的 `偏利好` / `偏利空` 指标卡可点击。
- 点击后进入一个专用的情绪新闻列表页，而不是复用当前通用 `News Feed` 外壳。
- 列表页按时间倒序展示对应情绪新闻，并为每条新闻展示更完整的信息卡。
- 点击列表项后进入现有新闻详情页。

## 非目标

- 不修改后端新闻接口、数据结构或情绪判定逻辑。
- 不改造现有 `News Feed` 页面为新的主入口。
- 不新增“按日期分组”“无限滚动”“多维筛选器”等超出本轮诉求的功能。

## 方案对比

### 方案 1：复用 `News Feed`，仅通过路由 query 预置筛选

优点：

- 改动最小。
- 复用现有筛选和加载逻辑。

缺点：

- 页面语义仍是通用新闻流，不像专门为“利好 / 利空”入口设计的落地页。
- 用户点进来后还会看到额外筛选器和通用文案，焦点不够集中。

### 方案 2：新增专用情绪新闻列表页

优点：

- 与 Dashboard 入口一一对应，路径更清晰。
- 可以把页面表达收敛为“时间倒序 + 完整卡片信息”，更贴合“规整好的新闻”。
- 不会影响现有 `News Feed` 的用法。

缺点：

- 需要新增一个视图、路由和测试。

### 方案 3：Dashboard 内联展开情绪新闻

优点：

- 跳转成本最低。

缺点：

- Dashboard 会承担列表浏览职责，信息层次变重。
- 不符合“点进去看新闻”的使用方式。

## 结论

采用方案 2：新增专用情绪新闻列表页，并把 Dashboard 指标卡升级为跳转入口。

## 详细设计

### 1. Dashboard 指标卡支持可点击入口

`HeroMetrics` 从纯展示组件调整为“可选跳转”的指标网格：

- 普通指标继续保持静态卡片。
- `偏利好` / `偏利空` 指标携带目标路由，渲染为可点击卡片。
- 卡片保留当前视觉风格，仅补充可点击状态提示（鼠标样式、悬停反馈、键盘可聚焦）。

`异动股票` 维持当前单独按钮入口，不借这轮顺手改成交互混合态，避免扩大范围。

### 2. 新增情绪新闻列表页

新增一个专用视图，例如 `SentimentNewsView.vue`，路由形态为：

- `/news/sentiment/positive`
- `/news/sentiment/negative`

页面只接受 `positive` / `negative` 两种情绪值；如果路由值不合法，则回退到 `positive`。

页面结构：

- 顶部标题区：显示当前情绪标题、简短说明和总条数。
- 主列表区：使用统一卡片按时间倒序平铺。
- 空状态：若对应情绪没有新闻，显示明确空文案。

### 3. 列表卡片内容

每条新闻卡片按“时间流 + 完整信息”组织：

- 标题
- 来源
- 市场
- 发布时间
- 摘要
- 情绪标签
- 提及股票（若有）

排序按 `published_at` 优先、`fetched_at` 兜底的时间倒序，保持与现有时间工具函数一致。

### 4. 数据加载策略

页面挂载时调用：

- `newsStore.loadNews({ sentiment_label, limit: 300 })`

为了让卡片里能显示主题和股票等更完整信息，页面再对首屏结果按需调用 `newsStore.loadDetail(id)`，复用当前 `News Feed` 的 detail hydration 思路。这样不改接口，只在前端补全展示。

### 5. 跳转行为

- Dashboard 点击 `偏利好` 指标卡：进入 `/news/sentiment/positive`
- Dashboard 点击 `偏利空` 指标卡：进入 `/news/sentiment/negative`
- 情绪新闻卡片点击：进入现有 `/news/:id`

## 测试策略

前端回归测试至少覆盖：

- `DashboardView` 中正负向指标卡存在正确入口。
- `HeroMetrics` 能区分静态卡片和可点击卡片。
- 新情绪新闻页会根据路由参数加载对应情绪的新闻。
- 情绪新闻页按时间倒序渲染，并能点击进入新闻详情。

## 风险与取舍

- 本轮复用 `newsStore.items` 作为列表数据源，进入情绪页后会覆盖通用新闻流缓存；这是当前 store 结构下的最小改动方案。
- 为了显示更完整卡片信息，页面会额外加载部分详情；如果后续列表规模继续增大，可能需要改成批量详情接口或分页策略。
- 当前只开放 `positive` / `negative`，不顺带扩展 `neutral` 或 `mixed`，避免让 Dashboard 入口和列表页职责发散。
