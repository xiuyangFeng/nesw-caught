# 日志可观测性安全加固设计

日期：2026-08-03

## 背景

日志系统重构已加入请求级 `request_id`、访问日志、前端错误上报和统一格式化。合并审查发现三个会削弱生产可用性的边界：正常访问日志在上下文清理后才写出、查询参数可能包含敏感令牌、页面卸载使用的 `sendBeacon` 无法携带应用鉴权头。

## 设计

1. 访问日志必须在请求上下文解除绑定前写出，保证普通响应和异常响应都携带同一个 `request_id`。
2. 保留非敏感查询参数用于排障，但将 `token`、`app_token`、`access_token`、`api_key`、`authorization` 的值统一替换为 `***`。
3. 响应中的 `X-Request-ID` 采用替换语义，避免下游已有同名头时产生重复值。
4. 页面卸载上报改为 `fetch(..., { keepalive: true })`，复用 `X-App-Token` 请求头；失败继续静默，不阻塞卸载。
5. 独立新闻抓取入口完整复用日志文件、轮转和格式配置；根目录 `.env.example` 明确从通配忽略规则中豁免并纳入版本控制。

## 验收

- 正常访问日志记录的 `request_id` 与响应头一致。
- 敏感查询值不出现在日志中，普通查询值保留。
- 页面卸载上报使用带请求头的 keepalive fetch。
- 日志专项后端测试、前端 logger 测试和差异检查通过。
