# LLM 模型设置表单稳定性优化设计

## 背景与根因

编辑模型配置并提交时，页面可能抛出 `raw.trim is not a function`，随后被模块错误边界替换为整页错误提示。

根因位于 `LlmConfigForm.vue`：成本与预算输入框使用 `type="number"`，Vue 会把用户输入转换为 `number`，但 `toPrice` 只接受 `string` 并直接调用 `trim()`。该异常发生在调用 API 之前，因此链接、模型名称和 API Key 即使有效也无法保存。

## 目标

1. 数字输入无论由字符串、数字或空值进入表单，都能安全转换，不再造成组件崩溃。
2. URL、必填文本、成本和预算在提交前给出清晰的字段级错误。
3. 编辑已有配置时说明 API Key 的保留规则；Base URL 改变时要求重新输入明文 Key，与后端约束一致。
4. 保存失败只展示在表单和 toast 中，不破坏整个模型设置模块。

## 方案

- 将价格转换函数改为接受 `string | number | null | undefined`，并区分“空值”和“非法值”。
- 为表单增加集中式校验结果：Provider、Model、Base URL、三个非负数字字段以及 API Key 更新规则。
- 编辑开始时记录原始 Base URL，用于判断地址是否发生变化；变化且 API Key 为空时禁用保存并提示原因。
- 输入字段增加 `aria-invalid` 和就地错误文案，保存按钮仅在表单有效且未保存时可用。
- 保留后端现有二次校验，不改变 API 契约或密钥持久化方式。

## 测试与验收

- 新增回归测试：数字价格/预算提交时不抛异常，并发送 number 类型。
- 新增验证测试：非法 URL、负数价格、修改 Base URL 但未重新输入 API Key 时不调用保存 API，并显示提示。
- 验证编辑已有配置、API Key 留空且 Base URL 未变化时仍可保存。
- 运行目标 Vitest、前端完整构建及相关后端 LLM 配置测试。

## 风险

- 本次不自动测试尚未保存的配置连接，避免“保存”动作额外产生外部模型请求。
- 不调整后端配置表结构和接口字段，兼容现有客户端。
