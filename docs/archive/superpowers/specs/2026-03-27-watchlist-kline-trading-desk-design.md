# Watchlist Kline Trading Desk Design

## 背景

当前 `watchlist` 详情区已经具备 K 线主图、副图指标、周期切换和相关新闻联动，但整体仍是卡片堆叠式布局。页面的信息优先级更像“功能展示页”，不像用户实际盯盘时需要的交易台：价格状态不够突出，主图不够大，量价关系不够紧凑，新闻事件也没有真正嵌回到图表语境里。

用户希望继续优化“看 K 线”体验，并借鉴东方财富等行情软件的设计思路。本轮目标不是做全量交易终端，而是在现有 watchlist master-detail 架构内，把右侧详情区升级成更像经典行情软件的三段式交易台。

## 目标

1. 让右侧详情区形成清晰的三段式结构：顶部行情摘要，中部主图交易区，底部辅助分析区。
2. 把 K 线主图变成页面视觉中心，强化“先看价格行为，再看解释层”的浏览顺序。
3. 保留新闻联动，但把新闻降级为辅助证据层，不再与主图抢主视觉。
4. 延续现有 `lightweight-charts` 和 `watchlistStore` 数据流，不引入新的图表库或后端接口。
5. 保持桌面优先，同时让移动端/窄屏下仍可顺序阅读。

## 非目标

1. 不实现盘口、逐笔、委托队列等实时交易功能。
2. 不新增后端行情字段或扩展 K 线 API 返回结构。
3. 不改动 watchlist 左侧列表的核心交互。
4. 不做全站主题重构，仅聚焦 `watchlist` 详情区和相关子组件。

## 推荐方案

采用“交易台式三段重构”：

1. 顶部摘要区负责快速扫描：
   - 股票名/代码
   - 最新价
   - 涨跌额、涨跌幅
   - 开盘、昨收、日内高低
   - 成交量
   - 更新时间
   - 周期切换工具条

2. 中部主图区负责价格行为：
   - 放大 K 线主图高度
   - 主图默认叠加 MA5/10/20/60
   - 成交量与主图保持同一视觉单元
   - 图内补充简洁图例和价格状态摘要
   - 新闻事件标记压缩成“事件筹码条”，不再只用页面底部按钮列表

3. 底部辅助区负责解释：
   - 左侧副图指标（MACD/KDJ/BOLL 切换）
   - 右侧新闻时间流，突出日期、来源、情绪和当前高亮事件
   - 说明性文本只保留简洁的 signal summary，不再占据主要空间

## 视觉方向

整体风格采用“深色交易台 + 琥珀高亮 + 冷色辅助”的方向，靠近经典行情软件但避免直接复刻。

1. 结构上减少大圆角卡片的“仪表盘感”，改成更紧凑、更接近终端面板的分区。
2. 主图区和副图区使用一致的面板边框与分割线语言，强调它们属于同一分析工作台。
3. 数字信息采用更强的字重与更紧凑的字距，强化价格读数的优先级。
4. 涨跌色延续当前橙涨绿跌的本项目约定，避免全局含义反转。
5. 新闻区色彩克制，只在当前高亮事件上使用明显强调色。

## 组件边界

### `WatchlistView.vue`

- 保持页面级路由和左/右两栏骨架。
- 顶部全局 header 和 market worker 状态卡保留，但弱化它们对详情区的视觉竞争。

### `StockDetailPanel.vue`

- 从“标题 + 三块内容堆叠”改成“顶部摘要 / 中部主图 / 底部辅助区”的总控组件。
- 管理当前副图 indicator、主图 overlay、新闻高亮时间。
- 负责把 quote、kline、news 重新组织成交易台式布局。

### `KlineChart.vue`

- 从单纯图表容器升级为主图交易面板。
- 新增：
  - 主图区标题栏
  - overlay 图例（默认显示 MA5/10/20/60，若存在布林带数据则在图例中明确标出 BOLL 可用状态）
  - 主图信息条（区间、K 数、新闻事件数）
  - 事件筹码条
- 保持现有图表 API，不要求新增后端字段。

### `IndicatorChart.vue`

- 视觉上作为主图下方的辅助面板，与主图区对齐。
- indicator 切换按钮做成更接近终端页签的样式。

### `RelatedNewsSidebar.vue`

- 从“新闻卡片列表”改成“新闻时间流”。
- 每条记录突出：
  - 日期/时间
  - 标题
  - 来源
  - 情绪
  - 与高亮事件的对应关系

## 数据流与状态

现有数据足以完成本轮改造，不新增 store 状态：

1. `quote` 用于顶部行情摘要。
2. `klineData.candles`、`indicators`、`news_events` 分别驱动主图、副图和事件筹码条。
3. `detailNews` 继续作为新闻流输入。
4. `highlightedEventTime` 继续作为图表事件与新闻流的联动键。

仅新增前端派生逻辑：

1. 从 quote 派生顶部关键指标展示项。
2. 从 candles 派生区间涨跌、最近收盘、K 线数量等摘要。
3. 从 news_events 派生事件标签的紧凑展示文案。

## 交互设计

1. 周期切换保持在详情区顶部，位置固定，减少用户眼动。
2. 主图默认渲染 `MA5/10/20/60` 四条均线；若后端返回布林带数据，则在图例中展示 BOLL 状态，但不强制切换主图 series 类型。
3. 点击主图事件筹码条时，高亮对应新闻日期。
4. 点击新闻流条目时，反向高亮对应事件日期。
5. 顶部摘要区必须固定展示：股票名/代码、最新价、涨跌额、涨跌幅、开盘、昨收、日内高/低、成交量、更新时间、周期切换工具条。
6. 顶部摘要区与主图区之间必须保持明显层级差：数字先于解释文本，新闻区弱于主图和行情数字。
7. 副图指标切换保持即时切换，不引入额外弹层。
8. 当 K 线数据缺失时，主图区仍保留完整骨架和空态提示，而不是整体塌陷。

## 测试策略

本轮以前端测试为主，遵循 TDD：

1. 先扩 `WatchlistView.test.ts`，锁定新的交易台文案和关键 data-role。
2. 扩 `KlineChart.test.ts`，锁定主图摘要和事件筹码条渲染。
3. 如有必要，为 `StockDetailPanel` 或 `RelatedNewsSidebar` 新增针对布局/状态的测试。
4. 最终执行：
   - `npm --prefix frontend run test -- --run src/views/WatchlistView.test.ts src/components/watchlist/KlineChart.test.ts ...`
   - `npm --prefix frontend run build`

## 风险与缓解

1. `WatchlistView` 打包体积已较大，本轮避免引入新库，控制在现有组件内重组。
2. `lightweight-charts` 在 jsdom 下能力有限，因此测试优先验证结构、交互和传参，不做像素级断言。
3. 如果主图面板承担过多文本说明，会重新变回“卡片堆叠”；因此说明性文本必须克制。
4. 移动端若直接照搬桌面密度会失衡，因此底部辅助区需允许自然折叠为单列。
