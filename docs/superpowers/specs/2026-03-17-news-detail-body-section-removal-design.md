# 新闻详情页正文区块精简设计

## 背景

当前新闻详情页在头部卡片中已经提供 `打开原文` 入口，用户可直接跳转来源页面查看完整正文。页面下方继续单独展示“正文内容”区块，会带来两个问题：

- 对多数来源而言，这块内容与“打开原文”的能力重复，增加阅读噪音。
- 当正文抓取失败或未回填时，页面会暴露 `正文暂不可用`、`extract_status`、`extract_error` 等技术性状态，削弱产品观感。

## 目标

- 移除新闻详情页中的“正文内容”独立区块。
- 保留头部卡片里的 `打开原文` 入口，作为查看完整正文的主路径。
- 不改动后端正文抓取、回填、数据结构与接口，避免扩大本轮范围。

## 非目标

- 不移除后端 `article` 字段，也不修改正文抓取任务。
- 不调整新闻详情页中的摘要、关联信息、同主题来源导航。
- 不新增新的正文预览交互。

## 方案

### 1. 新闻详情页只保留摘要，不再渲染正文抓取卡片

`NewsDetailView.vue` 顶部主卡片继续展示标题、摘要、来源、时间和 `打开原文` 链接。原先单独的“正文内容” `SectionCard` 整块删除，不再展示：

- `detailBody`
- `detail.article.extract_status`
- `detail.article.extract_error`

### 2. 行为边界保持前端展示层

本轮改动只作用于详情页展示：

- API 返回的 `article` 数据继续保留，避免影响其他页面或后续实验。
- 页面不再消费正文抓取状态，减少用户接触内部抓取语义。

### 3. 用前端视图测试做回归约束

新增一个最小组件测试，验证新闻详情页在有详情数据时：

- 仍能看到 `打开原文`
- 不再出现“正文内容”标题
- 不再出现 `success` / `failed` 这类正文抓取状态文案

## 风险与取舍

- 删除正文区块后，站内将不再提供正文兜底预览；但当前产品路径已明确以 `打开原文` 为准，这一取舍符合用户诉求。
- 本轮不删除后端字段，因此数据库和接口里仍会保留正文抓取数据；这是有意保守处理，便于后续恢复或复用。
