# 自选股搜索添加与删除交互改造

## 背景

当前自选股页 (`frontend/src/views/WatchlistView.vue`) 仍然采用左侧表单手工输入 `symbol`、`display_name` 的方式添加股票。这个流程有两个明显问题：

1. 用户必须自己知道并输入完整代码，输入门槛高，尤其是港股代码和中英文名称映射不直观。
2. 自选股列表只支持查看和跳转详情，不支持在页面内删除，维护列表成本高。

同时，现有后端 `backend/app/api/routes/watchlist.py` 只有列表、创建、关联新闻三个接口，没有候选股票搜索能力，也没有删除能力。

## 目标

在不改变现有 watchlist 行情与相关新闻联动模式的前提下，完成以下改造：

- 将“添加自选股”和“自选股总览”合并为一个主卡片，在表格上方提供单一搜索添加栏。
- 支持按股票代码、中文名、英文名任意片段做候选联想，用户选择后再添加，无需手工录入完整代码。
- 在自选股总览表格中提供删除功能，并在删除前进行二次确认。
- 保持现有 `POST /api/watchlist` 自动关联新闻能力不变。

## 设计

### 页面结构

自选股页改为两列：

- 左侧主区域：搜索添加栏 + 自选股表格
- 右侧辅区域：现有“关联新闻”预览继续保留

左侧主区域顶部增加一个“搜索添加”工具带，包含：

- 搜索输入框：用于输入名称/代码片段
- 候选下拉面板：展示匹配股票
- 阈值输入框：保留现有异动阈值能力
- 添加按钮：将当前选中候选加入自选股

原先单独的“显示名称”和“市场”输入控件不再要求用户手填，而是由候选项自动回填。

### 候选库与搜索方式

候选库采用“内置候选清单 + 前端本地过滤”的方式，不走实时外部搜索。

候选项数据结构至少包含：

- `symbol`
- `display_name`
- `market`
- `aliases`（可选，包含中文名、英文名、简称、数字代码等可匹配别名）

搜索匹配规则：

- 输入代码前缀或任意片段可匹配 `symbol`
- 输入中文名片段可匹配 `display_name` 或 `aliases`
- 输入英文名片段可匹配 `display_name` 或 `aliases`
- 已在自选股中的候选项仍可展示，但标记为“已添加”并禁止再次提交

这样可以确保输入“腾”“腾讯”“700”“apple”“tesla”时都能给出候选，且不依赖每次击键都访问服务端。

### 后端接口

新增两个接口：

#### 1. `GET /api/watchlist/candidates`

返回可供前端搜索的股票候选列表。后端维护一份内置候选源，前端首次进入页面时加载并缓存。

选择新增接口而不是把候选直接写死在前端，原因是：

- 候选源可以集中维护
- 后续扩充港股/美股名单时不需要重新改动前端搜索逻辑
- mock 与真实环境可共用同一数据契约

#### 2. `DELETE /api/watchlist/{symbol}`

按 symbol 删除对应自选股项。

删除时：

- 如果 symbol 不存在，返回 404
- 删除成功返回 204
- 不联动删除新闻数据，只移除 watchlist 项本身

### 前端交互流程

#### 添加流程

1. 页面初始化时加载：
   - 自选股列表
   - 自选股行情
   - 股票候选库
2. 用户在搜索框输入关键字
3. 前端基于候选库做本地过滤，展示前若干条结果
4. 用户点击候选项后，自动选定 `symbol / display_name / market`
5. 用户可选填阈值
6. 点击“添加到自选股”，调用现有 `POST /api/watchlist`
7. 添加成功后刷新 watchlist、行情和相关新闻，并默认选中新加股票

#### 删除流程

1. 用户点击表格行内“删除”
2. 前端阻止该点击触发行跳转
3. 弹出浏览器确认框
4. 用户确认后调用 `DELETE /api/watchlist/{symbol}`
5. 删除成功后刷新 watchlist 与行情
6. 如果删除的是当前选中股票：
   - 清空该 symbol 的相关新闻缓存，或切到剩余列表第一项
   - 确保右侧区域不继续显示已删除标的的内容

### 状态管理

`watchlistStore` 需要新增：

- 候选列表状态
- 候选加载状态 / 错误状态
- 当前搜索关键字
- 当前选中的候选项
- 删除中的 symbol / 删除错误状态
- 删除动作方法

保留现有：

- watchlist 列表加载
- 行情加载
- 相关新闻加载
- 创建 watchlist 的错误提示

### 表格改造

`WatchlistTable` 增加操作列和删除事件：

- 维持整行点击进入详情页
- 新增每行删除按钮
- 删除按钮使用独立点击事件，避免冒泡到行选择逻辑

### 不做的事

- 不接入实时在线股票搜索
- 不改动单股详情页结构
- 不修改添加后自动关联新闻的策略
- 不在本轮引入复杂弹窗组件，删除确认使用浏览器原生确认框即可

## 测试策略

### 后端

- 新增候选接口测试，确认返回候选数据
- 新增删除接口测试，确认：
  - 正常删除返回 204
  - 删除后列表中不再存在该 symbol
  - 删除不存在的 symbol 返回 404

### 前端

- store/API 测试：
  - 候选列表加载
  - 删除动作成功与失败
- 视图/组件测试：
  - 搜索栏输入后展示候选
  - 选中候选后允许添加
  - 已添加股票显示禁用态
  - 点击删除按钮时触发确认与删除，不触发行选择

## 风险与后续事项

- 内置候选库的覆盖范围取决于首版维护的数据清单，若后续需要更多股票，需要补充候选源。
- 前端本地过滤在候选量较小时体验稳定；如果后续候选量扩展到数千级以上，再考虑切换到后端查询或更细的索引结构。
- 删除 watchlist 后并不会删除已有价格快照和新闻关联，这是有意保持数据独立，避免误伤历史数据。
