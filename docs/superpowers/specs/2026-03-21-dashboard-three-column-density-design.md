# Dashboard 三列高密度布局设计

## 背景

当前 `Dashboard` 采用“上方主题聚合 + 自选股异动，下方最新新闻”的两段式结构。`资讯主题聚合` 一旦主题数变多，页面主滚动会被明显拉长，用户需要持续下滑才能看到 `最新新闻`，与总览页应该优先暴露最新动态的目标相冲突。

## 问题

- `主题聚合` 和 `最新新闻` 处于上下关系，长主题列表会直接把新闻入口整体挤到首屏之外。
- 三个模块的信息密度不一致，`News Feed` 条目视觉高度过大，单位屏幕承载量偏低。
- Dashboard 更像“长内容页”，而不是“多源情报看板”。

## 目标

- 桌面端把 `自选股异动`、`资讯主题聚合`、`News Feed` 改成同排三列。
- 三列使用固定可视高度与列内独立滚动，避免任一列拉长整页。
- 压缩字号、间距和摘要长度，提高信息密度，但保持可读性和现有视觉语言。
- 不改后端接口、不改 store 契约、不改变各入口的跳转语义。

## 非目标

- 不在 Dashboard 内新增筛选、排序、分页或跨列联动。
- 不调整 `Watchlist`、`TopicDetail`、`News Feed` 页面本身的数据模型。
- 不引入新的聚合 API 或后端字段。

## 方案对比

### 方案 A：均衡三列

三列等权或近似等权，每列都改为中等密度卡片。

优点：改动最小，结构稳定。  
缺点：不能突出 `News Feed`，对“快速看到最新新闻”的改善有限。

### 方案 B：新闻优先三列

三列并排，但 `News Feed` 略宽于另外两列，形成“新闻主列 + 两个情报侧列”的结构。

优点：最符合用户要先看到最新新闻的目标，同时能保留主题和异动的总览价值。  
缺点：需要针对三列内容形态分别做紧凑化处理。

### 方案 C：终端式超高密度面板

三列全部进一步缩小字号和行高，尽量接近交易终端列表。

优点：单位面积承载信息最多。  
缺点：可读性风险更高，视觉变化更大，也更容易破坏当前已建立的页面层次。

## 决策

采用方案 B。

- 桌面端三列宽度约为 `0.9 / 0.95 / 1.15`，对应 `自选股异动 / 资讯主题聚合 / News Feed`。
- 三列共享同一行高度，在桌面端启用列内独立滚动。
- 移动端回退为单列纵向堆叠，不保留多列独立滚动，避免窄屏滚动体验恶化。

## 布局与交互

### 桌面端

- `dashboard-grid` 改为三列布局。
- 每个模块外层卡片保持标题区固定，内容区成为可滚动容器。
- 用户可在不移动整页的前提下分别浏览主题、异动和新闻。

### 移动端

- 沿用单列堆叠。
- 不设置固定列高与列内滚动，保持自然页面滚动。

## 内容密度策略

### 自选股异动

- 保留顶部摘要区，但进一步压缩高度。
- 列表项收紧为单行主信息 + 单行辅信息：
  - 名称
  - 代码 / 市场
  - 异动原因
- 保留底部跳转到 `/watchlist` 的入口。

### 资讯主题聚合

- 继续沿用主题卡，但减少内边距、缩小标题字号。
- 摘要最多显示 2 行。
- 元信息压缩为一行，减少垂直占用。

### News Feed

- 不复用当前大尺寸新闻卡的表现形式，改为更紧凑的列表行。
- 每条只保留：
  - 情绪标签
  - 来源
  - 时间
  - 标题
  - 1 行摘要
- 保留跳转到完整 `/news` 页的入口。

## 数据与边界

- `DashboardView.vue` 继续消费：
  - `marketStore.abnormalMovers`
  - `topicStore.topTopics`
  - `newsStore.dashboardItems`
- 所有聚合、截断和压缩展示逻辑保留在 Dashboard 视图层，不进入 store。
- `News Feed` 列默认只展示前若干条 `dashboardItems`，完整浏览仍通过 `/news` 完成。

  - 桌面布局具备三列结构标识
  - 三列各自存在独立滚动容器标识

  - `自选股异动` 仍只展示 3 条预览

  - `npm --prefix frontend run test -- --run src/views/DashboardView.test.ts`

## 风险

- 固定高度过小会让某些笔记本屏幕的首屏显得压迫，因此高度应采用相对保守的 `clamp/calc` 策略，而不是绝对大高度。
- 列内滚动如果滚动条样式过重会影响观感，需要维持轻量视觉。
- `News Feed` 在 Dashboard 内改为紧凑模式后，需避免和完整 `/news` 页的阅读体验混淆，因此应明确保持“入口预览”定位。
