## 1. 背景：现状画像（实测）

项目历经三层演进：2026-03 新闻聚合（107 commits）→ 2026-07 个股情报（108 commits）→ 2026-08 量化交易台（22 个大提交，并接管首页）。目前 21 个前端路由、5 组导航、后端 services 约 2.4 万行。

真实使用数据揭示"引擎在转、下游没人用"：

| 模块 | 数据量 | 结论 |
|---|---|---|
| 新闻引擎 | `news_item` 21,386；正常运行时每天 1,700～2,700 条 | 持续运转 |
| 行情 | `price_snapshot` 28.9 万；`watchlist_item` 4（智谱 / 东山精密 / 阿里 / 寒武纪） | 运转，但只盯 4 只 |
| 量化台 | 选票 run 4、回测 1、模拟盘成交 0、组合提案 0；日线仅 30 只、停在 2026-08-18；财务 2 只 | 骨架完整、几乎未用、数据已陈旧 |

结构性重复：两个回测（`/analytics/backtest` 与 `/desk/backtest`）、两个运维页（`/ops` 与 `/desk/ops`）、两个个股详情（`/watchlist/:symbol` 与 `/desk/stocks/:symbol`）、两个组合（`/portfolio` 与 `/desk/portfolio-proposal`）。

## 2. 用户与场景（访谈结论）

- **身份**：真金白银交易的个人投资者；主做 **A 股**，但关注美股、亚太（日韩）对 A 股的传导。
- **替代品与痛点**：现用同花顺——**注意力被打散**，且**视野被局限**。
- **定位一句话**：**输入要宽（全球），输出要窄（只给结论）。**
- **使用节奏**：要实时，但不会一直盯 → 系统替用户盯盘，只在值得时提醒；盘后集中复盘。
- **"大新闻"优先级**：持仓 > 关注板块 > 可能引发次日异动。
- **"机会"来源**：新闻驱动、盘面驱动、主题驱动、叠加——全部汇入**同一份清单**，而不是多个页面。
- **AI 角色**：盘后简报 + 翻译/总结海外新闻 + 给出明确看法；海外→A 股的传导关系**由 AI 判断，用户修补**。
- **持仓**：愿意录入真实成本与仓位。
- **做窄**：删除量化台（后续需要再扩展）、删除 AI 对话；删除方式为**直接删代码**（git 历史可找回）。

## 3. 目标形态

```
① 全球输入（宽）   美股 / 亚太 / A 股新闻 + 隔夜与亚太指数
        ↓
② 传导映射         AI 判断：这条消息影响 A 股哪些板块 / 个股、方向、强度；用户可修正并沉淀
        ↓
③ 优先级过滤       持仓 > 关注板块 > 次日潜在异动
        ↓
④ 输出（窄）       盘中：站内提醒    盘后：复盘简报 + 明日关注清单    早间：隔夜简报
```

| 时段 | 系统 | 用户 |
|---|---|---|
| 盘中 | 实时抓新闻与行情、AI 筛选、命中规则即生成站内提醒 | 偶尔打开，只看提醒 |
| 盘后 | 自动生成复盘简报 + 明日关注清单（每项标注理由：新闻 / 盘面 / 主题 / 叠加） | 10～15 分钟读完并修正 |
| 夜间 | 不打扰；海外事件归集 | — |
| 早间（开盘前，默认 08:00） | 生成隔夜简报（美股收盘、美联储、海外财报对 A 股持仓/板块的影响） | 开盘前看一眼 |

### 3.1 首页「盯盘台」（仪表盘形式）

用户要求新首页做成仪表盘。布局（自上而下）：

1. 状态条：当前时段（盘前/盘中/盘后/夜间）、下一份简报时间、未读提醒数。
2. 全球指数条：标普、纳指、VIX、日经、KOSPI、恒生、上证、沪深300。
3. 左：**今日大新闻**（AI 筛选后的少量条目，每条带影响标签：持仓/板块、方向·强度、来源与是否海外译）；右：**持仓**（今日涨跌、仓位、浮盈亏，超过 ±5% 高亮）。
4. **明日关注**（每只带理由标签：新闻 / 盘面 / 主题 / 叠加）、**提醒流**（站内，立即/合并）、**本周日历**（持仓财报、宏观事件）。
5. **简报区**：盘中显示早间隔夜简报，盘后切换为复盘简报。

现有 `/dashboard` 的情绪仪表、恐慌贪婪、涨跌榜等组件按需保留为次级区块或移除，P4 实现时再定。

## 5. 新增能力

### 5.1 AI 分层漏斗（成本控制）

正常运行时每天 1,700～2,700 条新闻、正文均长约 1,240 字，不能每条全文过 AI。

| 层 | 做什么 | 量/天 | 估算 token/天 |
|---|---|---|---|
| L0 规则 | 去重、个股名匹配、来源过滤 | ~2,500 | 0 |
| L1 粗筛（便宜模型） | 标题+摘要，批量 20 条/次：与持仓/板块相关性、重要度 | ~2,500 | ~40 万 |
| L2 精读（强模型） | 全文：影响的 A 股板块/个股、方向、强度、理由 | Top 50～100 | ~20 万 |
| L3 简报 | 盘后简报 + 明日关注；早间隔夜简报 | 2 次 | ~5 万 |

合计约 65 万 token/天，约 2,000 万/月（输入约 1,700 万、输出约 300 万）。

用户提供 `gpt-6.1-terra` 单价：输入 0.15、输出 0.75（**按美元 / 百万 token 理解，待确认单位**）。据此：

- 全部走 terra：1,700 万 × 0.15 + 300 万 × 0.75 ≈ **$4.8/月**。
- 即使 L2 放宽到每天 300 条全文，也约 **$10/月**以内。

结论：成本不再是约束，**改为单模型（terra）**，取消 DeepSeek 分工以降低复杂度；分层仍保留，但目的变为**时延与限流控制**，L2 上限放宽到 200～300 条/天。若单位实为每千 token，则成本 ×1000（约 $4,800/月），须回到双模型 + 严格分层方案。

附带修复：现有 DeepSeek 配置 `output_price_per_1k=1.0`（≈ $1000/M）疑似误填，会使 Token 账本成本失真。

### 5.2 传导映射与用户修正

- L2 输出结构化影响：`(news_id, target: 板块|个股, direction: 利多|利空|中性, strength: 强|中|弱, rationale)`。
- 用户可在新闻详情/个股详情中修正（改方向、改强度、删除、新增）。
- 修正落库为"传导规则"，作为后续 L2 判断的 few-shot / 上下文；逐步沉淀为用户专属的产业链传导表。

### 5.3 提醒规则（站内）

| 级别 | 方式 | 事件 |
|---|---|---|
| 立即 | 单条站内提醒 | 持仓重大新闻；持仓**全天涨跌幅超过 ±5%**（统一阈值，不分股票）；海外重大事件 |
| 合并 | 每 30 分钟最多一条合并提醒 | 关注板块异动；AI 发现的新机会（自选外） |
| 防刷屏 | — | 同一标的冷却时间；每日上限 |
| 夜间 | 不提醒 | 夜间事件归入早间隔夜简报 |

### 5.4 真实持仓

持仓与关注合并后支持成本、数量；提醒和简报中显示"涉及仓位/浮盈亏"，而不仅是"与该股相关"。

- 4 个账号：DeItaone、FirstSquawk（彭博/路透快讯转发号）、eWhispers（财报日历）、MiniMax_AI（公司官方号）。
- 用"X 推文 vs 新闻库"做覆盖率比对：**无法得出结论**。真实推文只在 2026-03-11～03-19，而新闻库最早数据始于 2026-06-12，两者没有重叠时间段。
- 现状：twitterapi.io 余额不足仍在持续轮询失败，属无效消耗。
- **用户决定：方案 D，删除 X 模块**（P1 执行）。原备选方案记录如下：
  - A. 小额充值 twitterapi.io 并降低轮询频率，与新闻源**并行跑一周**做覆盖率与时效比对，再决定去留；
  - D. 直接依赖华尔街见闻 / 财联社等已接入源（同类快讯，通常晚几分钟），删除 X 模块。
  - 不采用自有账号 cookie 抓取（违反 X 服务条款、有封号与断流风险）。

## 9. 风险

- **删除不可逆的数据**：`market_data.db` 与量化相关表删除前备份；代码靠 git 历史找回。
- **"新闻↔个股关联"被量化模块共写**：`quant/mention_backfill.py`、`quant/radar/ingest.py` 也写 `news_stock_mention`；主写入方 `news_signal_pipeline.py` 不依赖量化模块，删除前用测试确认关联写入不减少。

- **站内提醒的可达性**：不做外部推送意味着只有打开页面才看到提醒（见 §10 待确认）。
