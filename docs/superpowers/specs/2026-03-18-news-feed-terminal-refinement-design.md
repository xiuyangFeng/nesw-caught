# News Feed Terminal Refinement Design

## 背景

当前 `News Feed` 首页已经从旧版暖色杂志风切到深色终端框架，但 `Primary Signal` 主卡仍保留明显的海报式表达：标题字号过大、列宽过窄、整体按纵向海报堆叠，导致首屏阅读压力偏高。同时，全局表面和高亮里仍混有较亮的橙色与偏浅的面板色，和“科技 / 金融 / 交易终端”的气质不一致。

本轮只优化首页主阅读流的视觉表达，不调整接口、数据结构、筛选逻辑或路由。

## 目标

- 把 `News Feed` 主视觉收敛成冷蓝灰交易终端风。
- 让 `Primary Signal` 从“纵向海报”改成“横向扫读主卡”。
- 保留 2 到 3 行摘要，确保用户能快速判断是否值得点开。
- 不改变现有数据流、点击跳转与响应式降级逻辑。

## 非目标

- 不重做 `Dashboard`、`Watchlist` 或其它页面结构。
- 不新增新闻排序规则或新的 editorial 打分逻辑。
- 不引入新的主题色体系以外的品牌色。

## 设计方案

### 1. 色彩系统收敛为冷蓝灰终端

全局 token 从“橙蓝混合辉光”收敛为“冷蓝灰底 + 少量青色高亮”：

- 背景改成更深的蓝黑渐变，保留极轻的冷色氛围光，但去掉大面积暖橙辉光。
- 面板主表面、输入框、卡片 hover 改为更硬朗的蓝灰黑层次，减少发白、发灰的浅色透明面。
- `accent/system` 统一偏向青蓝信号色，用于标签、焦点态、标题前导和轻量 hover。
- 涨跌色继续保留红绿语义，但饱和度压低，避免荧光感。

### 2. Primary Signal 改为紧凑横向信息结构

`LeadStoryCard` 改成三段式：

- 顶部：标签、情绪 pill、市场标签，维持一行终端式信号头。
- 中部：单行或最多两行的主标题，不再使用海报级超大字号。
- 底部：先显示 2 到 3 行摘要，再用一条横向 meta 带承载来源、时间、主题热度和关联股票数。

卡片整体维持单块主卡，但内部改成更低高度、更高信息密度的终端面板，而不是杂志封面。

### 3. News Feed 首屏信息结构优化

`NewsFeedView` 中 `Primary Signal` 区块仍保留在最前，但优化外层布局节奏：

- `edition-surface` 和 `editorial-flow` 间距略收紧，让主卡、次级卡片和流卡片更像同一终端工作区。
- `edition-head` 文案不再抢占视觉中心，真正的阅读焦点回到主卡。
- 保持当前 `Signal Queue` 和 `News Stream` 的顺序不变，避免影响现有阅读心智。

## 组件边界

- `frontend/src/assets/main.css`
  - 负责全局冷蓝灰 token、背景、表面色和语义色修正。
- `frontend/src/components/news/LeadStoryCard.vue`
  - 负责主卡结构与样式压缩，是本轮核心变更点。
- `frontend/src/views/NewsFeedView.vue`
  - 负责首屏容器间距和主区块节奏微调。
- `frontend/src/views/NewsFeedView.test.ts`
  - 负责验证首页仍渲染 `Primary Signal` 等关键结构。
- 如需新增更精确断言，可补到 `LeadStoryCard` 独立测试或现有首页测试中。

## 响应式与可读性

- 桌面端优先保证“标题一眼可扫、摘要快速预判、元信息横向对齐”。
- 在较窄宽度下允许 meta 带自动换行，但标题不恢复为巨型海报样式。
- 颜色对比度继续满足深色背景下的可读性，正文摘要与次级信息维持明显层级。

## 测试与验证

- 先写前端测试，约束主卡不再使用旧的 `Lead Story` 海报文案样式，而是新的终端标签和结构钩子。
- 跑针对性的 Vitest。
- 跑 `npm --prefix frontend run build` 验证样式和模板改动可通过生产构建。

## 风险

- 本轮主要依赖样式和模板结构调整，风险集中在测试选择器、断点下的文本换行与首页视觉层级变化。
- 如果主标题文本极长，仍可能在个别桌面宽度下占用两行；这属于允许范围，但需要避免重新拉高整张卡片。
