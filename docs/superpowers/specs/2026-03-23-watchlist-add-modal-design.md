# Watchlist Add Modal Design

## Context

当前 `/watchlist` 仪表盘已经恢复了候选搜索、手动刷新、删除等基础能力，但“添加自选股”仍然停留在左栏内联点击候选即提交的轻量实现。这个实现虽然可用，但体验上仍有几个明显问题：

- 搜索、选择、提交三件事挤在左栏同一个区域，误触成本高
- 用户无法在提交前确认即将添加的股票
- `alert_threshold` 仍然没有一个清晰、独立的填写位置
- 左栏当前职责已经偏重，再继续堆叠表单会压缩盯盘主流程

目标是把“添加自选股”补成一个更完整但仍然高效的 modal 流程，同时不引入多步 wizard 的冗余感。

## Approaches Considered

### Approach A: 单层混合型 Modal（推荐）

点击左栏入口后弹出一个单层 modal。用户先搜索并选中候选，默认可以直接添加；如果需要，可以展开“高级设置”填写阈值后再提交。

优点：

- 主路径最快，符合“直接添加”的诉求
- 高级设置仍然存在，但不会干扰默认流程
- 实现边界清晰，不需要引入复杂状态机

缺点：

- modal 内部需要同时容纳搜索区、候选区和设置区，布局要控制好密度

### Approach B: 双步 Wizard

第一步选股票，第二步填高级设置，再提交。

优点：

- 流程强约束，信息分层明确

缺点：

- 默认路径变慢
- 与“选中后直接添加”的目标冲突

### Approach C: 右侧抽屉

从左栏右侧滑出一个抽屉，承担搜索和设置。

优点：

- 保持当前页面上下文，不完全遮挡图表

缺点：

- 当前 master-detail 已经占满横向空间，抽屉会进一步压缩详情区域
- 移动端和窄屏适配更复杂

## Recommended Design

采用 Approach A：单层混合型 modal。

---

### 一、入口与整体结构

左栏顶部不再把搜索输入框常驻展开，而是替换成一个显式入口：

- 主按钮：`搜索 / 添加自选股`
- 次级按钮继续保留：`立即刷新一轮`

点击主按钮后打开 `WatchlistAddModal`。modal 使用居中浮层 + 半透明遮罩，默认聚焦到搜索框。关闭方式支持：

- 右上角关闭按钮
- 点击遮罩
- `Esc`

modal 关闭时需要清空本次临时状态：

- 搜索关键词
- 当前选中候选
- 高级设置展开状态
- 高级设置输入值
- inline 错误信息

### 二、Modal 内部布局

modal 内容分成三段：

1. 顶部：标题、副标题、关闭按钮
2. 中部：搜索框 + 候选列表
3. 底部：选中股票确认卡 + 提交区

布局示意：

```text
┌─────────────────────────────────────┐
│ 添加自选股                    [×]   │
│ 搜索代码、中文名或英文名             │
├─────────────────────────────────────┤
│ [搜索框__________________________]  │
│                                     │
│ 候选列表                            │
│  Tencent         0700.HK      [选中] │
│  Alibaba         BABA         [选中] │
│                                     │
├─────────────────────────────────────┤
│ 已选中：Tencent · 0700.HK           │
│ [展开高级设置]                       │
│   阈值（可选） [______]              │
│                                     │
│ [取消]                 [直接添加]    │
└─────────────────────────────────────┘
```

### 三、核心交互

#### 1. 搜索与候选选择

- 输入框支持按 symbol / display_name / aliases 模糊匹配
- modal 打开时若搜索词为空，不展示候选列表，避免信息噪声
- 点击候选项只会“选中”，不会立刻提交
- 当前选中项需要明显高亮

#### 2. 默认提交路径

- 选中候选后，主按钮 `直接添加` 立即可用
- 若用户不展开高级设置，则用：
  - `alert_threshold = null`
  - `alert_mode = "fixed"`

#### 3. 高级设置

- 默认收起，通过 `展开高级设置` 切换
- 当前只暴露一个字段：`阈值（可选）`
- 不新增新的提醒模式，继续沿用现有 `fixed`
- 若填写非法数字，错误直接在 modal 内提示，不关闭弹层

#### 4. 提交成功与失败

成功后：

- 关闭 modal
- 清空临时状态
- 刷新 watchlist
- 自动选中新加入的股票
- 右侧详情面板切换到该股票

失败后：

- modal 保持打开
- 错误显示在底部提交区
- 不丢失已选候选和已输入阈值

### 四、状态归属

为了避免把临时 UI 状态塞进业务 store，本次 modal 的临时状态放在 `WatchlistView` 本地：

- `isAddModalOpen`
- `addModalQuery`
- `addModalSelectedCandidate`
- `addModalAdvancedOpen`
- `addModalAlertThreshold`

`watchlistStore` 只继续负责真正的业务提交：

- `createWatchlist(payload)`
- `createLoading`
- `createError`

这样业务状态和临时 UI 状态边界更清晰，也更容易测试。

### 五、测试策略

前端至少补以下测试：

- 点击左栏入口可以打开 modal
- 输入搜索词后展示候选项，但点击候选只选中、不自动提交
- 选中候选后点击 `直接添加`，按默认参数调用 `createWatchlist`
- 展开高级设置后，阈值会随提交一起传入
- 创建失败时 modal 不关闭，错误继续显示
- 成功后 modal 关闭并切到新股票

## Expected Outcome

完成后，“添加自选股”会从左栏内联即点即提交流程升级为一个更明确、更安全的 modal 流程。默认用户仍然可以快速添加，但在需要时也能自然地补充阈值设置，不会打断 watchlist 仪表盘的主视线，也不会让左栏继续承担过多表单职责。
