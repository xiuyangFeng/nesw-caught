# K 线图专业终端化优化设计

## 背景

当前自选股详情页的 K 线模块已经完成了工作台基础接入：周期切换、画线工具、指标模板、右侧工作台和副图切换都已连通，基础功能闭环已经具备。

但这版仍明显偏“功能接线完成”而不是“专业看盘终端”：

- 主图虽然可用，但信息层次还比较平，图表主体的压迫感和专注度不够
- 顶部摘要、工具条、副图读数、右侧工作台之间还缺少清晰的主次关系
- 当前主图缺少面向读盘的即时读数层，用户只能从右侧或静态摘要中取数
- 右侧工作台和副图区的布局密度还不够像专业行情软件，更接近管理面板而不是交易工作台

用户已明确本轮优先级是“图表观感与专业度”，并授权不再逐步征求确认，可直接推进到完成。

## 目标

在不替换图表库、不扩大到高风险交互重构的前提下，把当前 K 线区域升级成更接近专业看盘终端的视觉与信息组织。

本轮目标：

- 让主图成为视觉中心，强化“图优先”而不是“面板优先”
- 重组头部、工具条、主图读数带、副图和右侧工作台的层级关系
- 增加轻量但有效的即时读数 HUD，让用户在图上就能读到关键行情信息
- 保留现有画线、模板、周期和副图能力，不引入新的后端依赖

非目标：

- 不在本轮把 overlay 交互做成 TradingView 级别
- 不新增后端接口或服务端持久化
- 不引入复杂动画、重型状态机或新的图表库

## 方案比较

### 方案 A：纯视觉皮肤升级

做法：

- 只调整配色、边框、阴影、圆角和局部 spacing
- 保持当前布局结构基本不动

优点：

- 改动最小
- 风险较低

缺点：

- 只能让界面“更精致”，不能让它真正更像专业看盘终端
- 信息密度和读盘路径问题仍然存在

结论：不采用。用户需要的是“专业度”而不只是“更好看”。

### 方案 B：结构重排 + 终端化视觉增强

做法：

- 保留现有 `KlineChart` 组合架构
- 把头部、工具条、主图区、十字读数带、副图区、右侧工作台重新编排
- 在主图内部增加悬浮读数 HUD 和角标式信息条
- 压缩非关键区域，把更多面积还给图表本身

优点：

- 可以明显提升专业感和读盘效率
- 风险可控，不需要推翻现有 store 和 overlay 结构
- 能为下一轮更深的交互优化留出清晰骨架

缺点：

- 需要同步调整组件结构、样式和测试
- 要处理无 hover 状态时的默认读数回退

结论：采用。这是当前投入产出比最高的路线。

### 方案 C：一步做到高保真交互终端

做法：

- 同时重做十字线、悬浮 tooltip、拖拽反馈、缩放联动和 overlay 精度

优点：

- 最接近目标形态

缺点：

- 会与当前第一版 overlay 实现强耦合
- 测试和实现复杂度明显扩大，交付风险高

结论：本轮不采用，留到下一轮。

## 设计总览

### 总体视觉方向

延续当前终端式深色基调，但从“卡片拼接”改成“交易工作台”方向：

- 主图区块更沉、更干净，减少无效装饰边界
- 强调琥珀橙作为主操作和主读数高亮色，辅以冷蓝作为次级信息色
- 信息展示从“大块面板”转成“贴图信息条、角标、标签和窄卡”
- 控件文案更短，尽量避免大段说明性文字

### 布局重构

`KlineChart` 内部拆成四个视觉层：

1. 顶部行情条
   - 显示品种、当前周期、数据状态、更新时间
   - 比现有头部更扁平、更贴近终端抬头

2. 主工具条
   - 周期、画线、清空、面板开关整合成单一控制带
   - 弱化卡片感，增强工作台控制感

3. 图表舞台
   - 主图作为绝对核心区域
   - 图内叠加图例、即时读数 HUD、画线浮层和空状态遮罩
   - 副图在视觉上收敛进同一舞台，但实现上仍保持独立的第二个 `lightweight-charts` 实例，不改成单 chart 重写

4. 侧边工作台
   - 继续承担模板、指标、技术读数
   - 视觉上改成更紧凑的“侧柜”，不与主图区争抢注意力

### 主图即时读数 HUD

新增一个主图 HUD，用来承接“专业度”提升的核心体验。

规则：

- 默认显示最新 candle 的 `开 / 高 / 低 / 收 / 涨跌幅 / 成交量`
- 当鼠标在主图区域移动时，HUD 切换到当前悬停 candle 的数据
- 如果当前 hover 时间没有精确命中 candle，则吸附到最近 candle
- HUD 放在主图左上角，以窄条 + 数值标签形式呈现
- 正涨用暖色，负涨用绿色，保持当前 K 线涨跌语义

这套 HUD 是轻量信息层，不要求真正画出完整十字准线；本轮只提供 hover 读数，不扩成复杂 cursor 系统。

hover 事件契约明确如下：

- `KlineDrawingOverlay` 在 `mousemove` 时发出 `hover-anchor-change`
- 负载结构为 `KlineDrawingAnchor | null`
- 在选择、绘制和空闲状态下都允许发出 hover 事件，因为它只负责读数，不改变现有 draft 流程
- `mouseleave`、overlay 不可用或无 candle 时发出 `null`
- 本轮不做节流，先依赖本地状态更新；若后续发现性能问题，再单独补节流

### 主图图例与状态角标

现有 `summary` 和 `legend` 从图外卡片改成图内角标式编排：

- 周期、范围、股票代码以顶部角标展示
- MA/BOLL 图例压缩到主图顶部或底部的细粒度标签带
- 当存在选中画线、活动模板、副图指标时，用更短的状态标签显示

目标是把静态说明从“独立大卡片”改成“贴图短读数”。

### 副图区优化

副图区保留，但视觉上做两点调整：

- 把副图切换按钮和最新读数收进一个更窄的控制条
- 缩减副图说明卡体积，避免把副图自己又做成第二个大面板

当右侧工作台折叠时，副图区域可以稍微增高，让整体更接近“图上读指标”的终端感。

### 右侧工作台优化

`KlineIndicatorWorkbench` 不再表现成独立“管理卡片”，而是改成更紧凑的专业侧栏：

- 顶部只保留当前模板名、模板摘要、当前副图指标
- 模板列表收成密度更高的库项
- 读数信息以窄网格展现，减少大块留白
- 与主图区使用统一的边框、背景和高亮语言

### 交互与回退

本轮交互只做低风险增强：

- 主图 hover 读数
- 右侧侧栏折叠时，主图区自动扩展
- 空状态和无数据时，HUD 与图内角标回退为占位内容
- 不新增会破坏现有画线逻辑的复杂拖拽行为

## 组件与状态影响

### `KlineChart.vue`

作为本轮主改造点，负责：

- 新布局结构
- hover candle 状态维护
- HUD 数据回退逻辑
- 主图角标、图例和副图区控制条

### `KlineDrawingOverlay.vue`

只做配合性调整：

- 在鼠标移动时向父层暴露当前吸附 candle 信息，事件名固定为 `hover-anchor-change`
- 保持现有 draft 和 drawing select 行为不变

### `KlineToolbar.vue`

调整为更紧凑的工作台控制带：

- 压缩按钮层级和 spacing
- 强化当前激活态
- 与图内专业终端风格统一

### `KlineIndicatorWorkbench.vue`

调整信息组织和密度：

- 当前模板区更短更紧
- 模板库项更像终端列表
- 副图切换和模板动作区缩成控制簇

## 测试策略

本轮继续遵循前端 TDD：

- 先为 `KlineChart.test.ts` 补主图 HUD、角标化摘要、侧栏收起后布局与副图区读数的新断言
- 在 `KlineChart.test.ts` 中补一条端到端断言，证明 overlay 发出的 hover 事件能切换 HUD 读数
- 新建 `KlineToolbar.test.ts`、`KlineIndicatorWorkbench.test.ts`，补组件级结构断言
- 新建 `KlineDrawingOverlay.test.ts`，覆盖 hover 事件发射测试
- 最小回归验证仍包括相关 Vitest 文件和 `npm --prefix frontend run build`

## 风险与后续

主要风险：

- 当前 overlay 并不直接依赖 lightweight-charts 的真实坐标体系，因此 hover 吸附只能基于前端现有 candle 序列近似映射
- 图内信息层增多后，需要注意测试不要和过度细碎的文案强耦合

后续可继续推进的方向：

- 真正的十字光标与 Y 轴价格读数联动
- 主图 hover 时的新闻事件同步高亮
- 更高保真的画线锚点、拖拽和对象编辑体验
